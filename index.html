    Client certificate hosts: on a TLS connection to one of these hosts the device presents the client certificate the app's KeyManager chooses (the key and chain the app registered, from its KeyStore), as a server that asks for one would get it. It needs the relay (the browser cannot present a client certificate): the key and chain go to the relay over its token-protected channel, only for these hosts, and live there in memory only. Other hosts never see them.

Apps that use Play services find it and get microG's local answers (availability, App Set ID, advertising ID, location). Still unavailable, with an explicit error: device registration, Google account sign-in, push (FCM), SafetyNet, Play Integrity and DroidGuard. Off (default), the device has no Play services. To mock from here, give a constant value for the return type (a reference accepts only null or "text"); rich values (Bundle, byte[], object) are only available through the Node API (platform.microg.mock). Some entry points deliver the result through a callback/coroutine: a value mock is counted as a hit but does not feed the result.

        Execution
        ⌄
        
              
              
        
              
              
        This number is the Java heap budget (VM objects and arrays; the other budgets grow with it). The browser uses more than that: DEX tables, CanvasKit, rasters and one JavaScript object per Java object. A tab above ~2–4 GiB may be killed by the browser. The engine limit is 2,097,152 objects (4 GiB is capped to it).
        
              
        
              
        
                Wasm core memory reopen the APK to apply
                
                
        
                  
                  
                  
                
        
                
        
                
        
                
        Only applies with the "WebAssembly core" engine (the default), when the APK is opened again. Dynamic: the heap starts small and grows as the app keeps objects alive, and each new thread takes 1 MiB; the two share, with no boundary between them, everything above the metaspace. Fixed: heap, metaspace and threads each get the size set here, and exceeding a ceiling fails naming it. Metaspace (linked classes and methods, grows with the app size) is a size in both modes. Memory is at most 2048 MiB and only takes RAM when used; the diagnostics summary shows how much of each part is in use.
        
                
              
        
              
              
        The VM runs the app's code many times slower than a device. A startup with hundreds of threads can exceed the default 25 s without being stuck: the "Instruction budget exceeded" report shows the threads still advancing. A longer time lets it finish; a real infinite loop is still ended with a report, only later.

                Redirect hosts
                0 active⌄
                
              
                Each rule sends the app's requests for one host to another destination, like an /etc/hosts entry that can also change the port and scheme. The app still sees the original URL; only the request the browser makes goes to the destination, and it does not need to be in “Allowed network hosts” (offline mode still applies). Source: https://api.example.com, api.example.com, host:port or *.domain. Destination: host, host:port or http(s)://host:port; without a scheme, localhost and 127.0.0.1 use http. A local server must answer CORS for the lab page (or use the CORS relay with --allow-private). Applies immediately, counts the responses of each rule and marks the requests in the Network panel.

                  Endpoint mocks
                  0 active⌄
                  
              
                  Debugging tool: an app request that matches a mock in the list is answered by the lab with the configured response and does not go to the network. The first active mock that matches, in list order, answers, ahead of the allowed hosts list, offline mode, Redirect hosts and the Proxy. Applies to HttpURLConnection, OkHttp and other clients over java.net.Socket, and to DownloadManager; WebView pages are loaded by the browser and do not go through the mocks. Each response is counted, marked in the Network panel (and in the HAR), cited in the Summary, and the first one of each mock logs a warning in Logcat.
