Plugins: ferramentas suas sobre o app em execução

Um plugin é um trecho de JavaScript que você escreve no laboratório. Ele observa a tela ativa, a árvore do Compose, os ViewModels, o Logcat e a rede do app, recorta partes da tela e mostra o resultado num painel abaixo do aparelho. Ele só lê: nada do que um plugin faz muda o app.

O que são

Cada plugin ligado roda num Web Worker só dele, separado da página e da VM. Um plugin lento ou preso num laço trava apenas o próprio Worker. As perguntas à VM passam por uma fila com limite de custo, e a saída vira blocos de texto, tabelas e imagens no painel Plugins.

Sem nenhum plugin ligado não existe Worker, timer, mensagem à VM nem gancho nos caminhos do app. Como um plugin se encaixa no resto do laboratório: arquitetura, ferramentas.

Onde ficam

  • Configuração: painel Controles do laboratório, seção Plugins (a última). O título mostra quantos estão rodando.
  • Saída: painel Plugins abaixo do aparelho, ao lado de Logcat, Rede e Compose. Ele aparece quando há pelo menos um plugin na lista e mostra um cartão por plugin: os blocos de saída, um selo curto, o console e os erros.
  • Armazenamento: a lista é guardada no localStorage deste navegador e vale para qualquer APK (não é por pacote). Cabem até 32 plugins, com até 200.000 caracteres de código cada.

Adicionar um plugin

  1. Abra Controles › Plugins.
  2. Clique em + Adicionar. O diálogo abre em branco, com um link para os exemplos: Nome, as opções de saída e Código. No editor, Tab insere dois espaços e Esc fecha.
  3. Escreva o código, ou copie um dos exemplos (Tela atual, Logs filtrados, Observar ViewModel, Componentes da tela, Árvore Compose resumida, Print na tela pronta, Botões do plugin e outros).
  4. Clique em Salvar. O plugin novo já vem ligado, vale para qualquer app e começa a rodar quando há um APK aberto.

O código é o corpo de uma função assíncrona: use await no topo à vontade. import estático não funciona; await import(url) funciona. O objeto global lab é a API.

Ligar, parar e editar

  • Caixa de seleção na linha do plugin: liga ou desliga. Desligado, o Worker dele é encerrado.
  • ↑ e ↓ mudam a ordem da lista (e dos cartões).
  • Editar abre o mesmo diálogo; ao salvar, o plugin recomeça com o código novo.
  • Remover pede confirmação e apaga o plugin da lista.
  • No cartão do painel Plugins, Parar encerra o Worker do plugin (útil se ele entrou em laço) e Reiniciar cria outro do zero.
  • Os cartões começam recolhidos: um clique no nome abre. Fechado, o cartão só atualiza o cabeçalho (estado, selo, “novos dados”) e não redesenha os blocos.
  • Ao criar ou editar o plugin, no mesmo diálogo do código: Atualização da saída automática (os blocos acompanham o plugin) ou manual (ficam parados até você clicar em Atualizar no cartão, que mostra “novos dados” quando há saída nova); e Altura dos blocos: Limitada (até 320 px, com rolagem, o padrão), Conteúdo inteiro ou Fixa (80 a 2000 px). O cartão fica simples: Atualizar, Parar e Reiniciar. Atualizar também chama lab.on('refresh') do plugin.
  • Um bloco com id é atualizado no lugar e mantém a rolagem quando o plugin escreve de novo.
  • ⤢ Expandir no cartão abre a saída do plugin numa janela grande, que continua atualizando; feche com × ou Esc.
  • Essas opções ficam com o plugin (vão junto na exportação) e mudá-las não reinicia o plugin.
  • A linha mostra o estado: rodando, iniciando, parado (com o motivo: desligado, parado no painel, só para outro pacote) ou erro, e quantos erros houve.

Filtro de pacote

Um plugin criado no diálogo vale para qualquer app: o diálogo não tem mais o campo Pacote. Um plugin que já tinha um filtro de pacote (salvo antes, ou importado de um JSON com packageFilter) continua com ele: a linha do plugin mostra “pacote …”, e quando o APK aberto não casa o plugin fica parado com o motivo “só para …”. Ao editar um plugin assim, o diálogo avisa e oferece Valer para qualquer app, que tira o filtro ao salvar.

No JSON, packageFilter vazio ou * é qualquer app; vários pacotes vão separados por vírgula ou espaço, e * funciona como curinga dentro de um nome (por exemplo com.exemplo.*). Dentro do código, lab.info.packageName diz qual app está aberto.

Exportar e importar

Exportar baixa um arquivo plugins-AAAAMMDD-hhmmss.json com a lista inteira. Importar lê um arquivo nesse formato (ou só um array de plugins) e acrescenta os plugins à lista.

{
  "format": "apk-web-lab-plugins",
  "version": 1,
  "plugins": [
    { "name": "Tela atual", "code": "lab.on('screen', tela => lab.ui.text(tela.activity ?? '—'));", "enabled": true, "packageFilter": "" }
  ]
}

Plugins importados chegam desligados: o código é de outra pessoa, então leia antes de ligar. Só os primeiros 32 da lista são importados.

A API lab

Eventos

ChamadaO que entrega
lab.on('screen', fn)A tela ativa mudou: { activity, activityStack, tasks, windows, dialogs, canGoBack, closed, packageName, frame }. Destinos do Navigation dentro da mesma Activity não contam como mudança de tela. Devolve a função que cancela.
lab.on('log', fn)Lotes (arrays) de linhas do Logcat: { seq, uptime, wall, pid, tid, thread, level, tag, message }.
lab.on('network', fn)Lotes de entradas do log de rede, novas ou atualizadas.
lab.on('refresh', fn)Você clicou em Atualizar no cartão do plugin. Para plugins que leem sob demanda (com atualização manual, por exemplo) em vez de vigiar o tempo todo.
lab.off(nome, fn?)Cancela uma escuta (ou todas daquele evento).

Consultas

Com locals: ['LocalContentColor', 'LocalMeuTema'], cada nó traz locals.LocalX: o valor que aquele composable vê, para diferenciar componentes por um Local numa chamada só. Para recortar qualquer componente: bounds com um retângulo na janela, element com um item de lab.layoutBounds() ou node com um nó de lab.composeTree() (usa o boundsInWindow dele); o recorte vem de todos os rasters sob a área, na resolução deles.
ChamadaO que devolve
await lab.screen()A tela atual, no mesmo formato do evento, sem trabalho na VM. screen.ready é a “Tela pronta”: { ready, activity, readySince, waitingFor, fragments }. Fica pronta quando a Activity está em onResume com o primeiro quadro desenhado, os fragments em RESUMED, e não há quadro, layout, mensagem da thread principal nem requisição de rede pendente por 300 ms.
lab.on('ready', fn)Chama fn(tela) cada vez que a tela fica pronta: uma Activity nova, um Recriar/Reabrir, uma navegação que assenta. Uma tela que anima sem parar (spinner, cursor piscando) não fica pronta; waitingFor diz por quê.
await lab.waitReady({ timeoutMs })Espera a tela ficar pronta (15 s por padrão); erro com code: 'timeout' e o motivo. Use antes de lab.screenshot().
await lab.composeTree({ maxNodes, locals })A árvore de layout do Compose: { owners: [{ nodes: [{ id, handle, parentId, depth, name, bounds, texts, editableText, role, testTag, actions, … }] }], totalNodes, truncated }. Custa dezenas de milissegundos na VM: no máximo uma por segundo por plugin.
await lab.layoutBounds({ names })As caixas que “Mostrar limites de layout” desenha (Views e nós semânticos do Compose), como no painel Compose: [{ key, kind, name, nameSource, bounds, size, texts, editableText, role, testTag, contentDescriptions, actions, modifiers, measurePolicy, type, hasImage }], com bounds em pixels da janela. Os nomes vêm de uma composeTree (mesmo limite de uma por segundo); names: false não consulta a VM.
await lab.screenshot({ key | bounds | element | node, maxWidth, type })Imagem da tela inteira, ou de uma caixa (key de layoutBounds), cortada do quadro que a página mostra, sem trabalho na VM: { blob, width, height, type, notes }. Padrões: maxWidth 1080, type 'image/png'. No máximo uma a cada 500 ms por plugin. Views que a página desenha com elementos próprios (widgets XML simples) não têm raster: ficam de fora da tela inteira (notes diz quantas) e a caixa delas responde no-image.
await lab.renderVariant({ endpointMocks, crops, tree, mode, timeoutMs })Renderiza em segundo plano outra instância da tela atual com outros mocks de endpoint (formato de lab.mock) e devolve imagens e dados dela: { image, images, views, semantics, composeTree, requests, mocks, settled, timedOut, waitingFor, notes }. crops: vários recortes de uma só renderização, cada um { selector: { name | testTag | text | contentDescription | role | viewId }, all, index } ou { rect }; tree: true traz a árvore do Compose da variante para escolher o que recortar. A instância é destruída ao final. mode: 'display' (padrão; a tela visível não recebe nenhum callback) ou 'cover' (ela é pausada, salva e parada, e depois retomada; com restoreState: true a instância nasce com o estado salvo, para apps de uma Activity com Navigation). Limites: roda no mesmo processo, então os mocks valem para o app todo durante a renderização e o que a resposta gravar em estado compartilhado permanece; um startActivity da instância é descartado (droppedStarts); a entrada do usuário espera; só rasters entram na imagem, como em screenshot. Padrões: timeoutMs 5000 (máx. 15000).
await lab.viewModels()Os ViewModels da tela: da Activity, dos fragments na tela e os guardados pelas entradas da pilha do Navigation. [{ handle, className, key, library, owner: { kind, label, className, handle } }].
await lab.fragments()Os fragments androidx na tela, com os filhos: [{ handle, className, who, tag, id, hidden, state, children }].
await lab.activity(){ handle, className } da Activity atual.
await lab.inspect(handle, opções)Os campos de um objeto em JSON. Opções: depth (2), maxFields (200), maxItems (20), maxString (1000).
await lab.field(handle, 'a.b.0.c', opções)Um valor por caminho: nomes de campo (um delegate Kotlin x$delegate responde por x), índices de lista ou array, chaves de mapa, size. Um StateFlow, LiveData, MutableState ou atômico é atravessado; x.value é o valor atual. Um WeakReference/SoftReference (ref.get), um by lazy do Kotlin e um ThreadLocal também são atravessados. Uma parte com pontos (uma chave de mapa) vai num array: ['registro', 'a.b.Tipo::escopo', 'value'].
lab.watch(handle, caminho, fn, opções)handle também pode ser { static: 'pacote.Classe' } para seguir um campo estático. Lê o campo a cada intervalMs (padrão 500, mínimo 250) e chama fn(valor, anterior) só quando muda. Se o objeto for coletado, o watch para e onError recebe o erro. Devolve a função que para.
await lab.statics('pacote.Classe', opções)Os campos estáticos de uma classe que o app já inicializou: { className, status, fields }. Serve para um object Kotlin, um companion, um singleton ou um contêiner de injeção de dependências guardado num campo estático. Uma classe ainda não inicializada responde status: 'not-initialized' e a lista declared: a consulta nunca roda o <clinit>.
await lab.staticField('pacote.Classe', caminho, opções)Um valor por caminho a partir de um campo estático, como lab.field: lab.staticField('a.b.Registro', 'atual.estado.value'). O primeiro nome é o campo estático (da classe ou de uma superclasse).
await lab.classes('parte do nome', { limit, initialized })As classes do APK cujo nome contém o texto (ou casam com '/regex/'): { items: [{ className, status, staticFields }], matched }. Para achar a classe que guarda um estático.
await lab.instances('pacote.Classe', { subclasses, limit, after, maxPages })Os objetos vivos de uma classe (subclasses e implementações incluídas, a menos que subclasses: false): { items: [{ handle, className }], scanned, done, next }. Varre o heap em páginas curtas; next continua uma varredura que parou (after).
await lab.referrers(handle, { limit, after })Quem segura um objeto: campos estáticos ({ kind: 'static', className, field }) e objetos cujo campo, célula de array ou slot interno aponta para ele ({ kind: 'object', handle, className, via }). Para descobrir o caminho até um objeto achado com instances.
await lab.compositionLocals(nó.handle, { only, depth })Os CompositionLocals de um componente do Compose: o que LocalX.current responde naquele nó. Pegue o handle do nó em lab.composeTree(). Devolve { count, locals: [{ name, declaredIn, kind, value }], values }; values.LocalContentColor é o valor direto. kind: static, dynamic (o valor atual do estado) ou computed (calculado pela composição; não é avaliado aqui). Só aparecem os Locals fornecidos no caminho até o nó; os outros valem o padrão. only aceita o nome inteiro ou parte dele (sem diferenciar maiúsculas), Classe.campo ou parte da classe do valor. O nome vem do campo estático que declara o Local, ou do campo de instância que o guarda (um Local dentro de uma classe ou de um objeto); num app minificado, é o nome renomeado. Cores do Compose vêm como { $kind: 'color', argb: '#AARRGGBB' }.
await lab.findCompositionLocal('LocalTema', { limit, budgetMs })Onde um Local é fornecido na tela, sem escolher o nó: lê o mapa de cada componente e agrupa por valor. Devolve { matches: [{ name, declaredIn, kind, valueType, value, nodes, node }] }: cada valor diferente, quantos componentes o veem e o handle de um deles. Bom para achar um Local seu e a instância que ele carrega.

Agir no lab

Um plugin também usa os controles do próprio laboratório, como você faria em Controles. Tudo fica visível ali e no Logcat; o app em si continua sem ser alterado por dentro.

ChamadaO que faz
await lab.reload('recreate' | 'reopen')Recarrega a tela atual: recreate (padrão) é o Activity.recreate(), que mantém o estado salvo e os ViewModels; reopen abre uma instância nova com o mesmo Intent. Igual aos botões ↻ da barra do aparelho.
await lab.mock({ method, url, status, headers, body, delayMs, query, id })Cria ou troca (mesmo id) um mock em Controles › Mock de endpoints, do pacote aberto: a próxima requisição que casar recebe essa resposta sem ir à rede. body pode ser texto ou um objeto (vira JSON). Devolve { id }; um mock inválido dá erro com o motivo.
await lab.unmock(id) · await lab.mocks()Remove um mock; lista os mocks do pacote com as respostas dadas.
const m = await lab.modal.open({ title, size, html })Abre uma janela na página, small, medium ou full (tela inteira), com botão de fechar e Esc. html é qualquer HTML, CSS e JavaScript seu: roda isolado na janela (um iframe sem acesso à página do lab). Na janela, window.lab.post(dados) manda para o plugin e window.lab.on(fn) recebe.
m.update({ title, size, html }) · m.post(dados) · m.close() · m.onMessage(fn) · m.onClose(fn)Troca o conteúdo, conversa com a janela e fica sabendo quando ela é fechada (user, code ou stopped, quando o plugin para).
await lab.dataUrl(imagem)Uma imagem (de lab.screenshot) como data: URL, para pôr no HTML de uma janela.

Rolar o app

O lab rola pelo caminho que a roda do mouse usa no aparelho: a ação ScrollBy do componente no Compose, ou View.scrollBy numa View. Ele lê onde a rolagem está, pede a diferença e lê de novo até parar no lugar; nada é escrito por fora do app. As posições são em px do aparelho, que no lab são iguais a dp (densidade 1).

ChamadaO que faz
await lab.scrollTo({ x, y, target }) · lab.scrollTo(300)Rola até uma posição em px a partir do início (um número sozinho é o y). Uma posição depois do fim para no fim. Devolve { element, key, x, y, maxX, maxY, percentX, percentY, unit: 'px', reached, steps, via }: onde parou, o curso da rolagem e se chegou.
await lab.scrollToPercent({ x, y, target }) · lab.scrollToPercent(50)Rola até uma porcentagem (0 a 100) do curso da rolagem, na vertical (y), na horizontal (x) ou nas duas. Mesma resposta.
await lab.scrollInfo(target)Onde a rolagem está, sem mover.
targetQual componente rolar, do mesmo jeito das outras consultas: { testTag } (ou só o texto do testTag), { text }, { key } ou um elemento de lab.layoutBounds(), { x, y } (um ponto da janela). Se o alvo não rola, vale o componente rolável que o contém. Sem alvo: o maior componente rolável da tela.

Listas preguiçosas (LazyColumn, LazyRow) só montam os itens visíveis e não sabem a própria posição em px. Nelas o lab usa o que é exato: o primeiro item (ScrollToIndex 0), o fim do conteúdo e o ScrollBy. scrollTo({ y }) rola essa quantidade de px a partir do primeiro item; 0 % e 100 % vão direto às pontas; uma porcentagem no meio faz o lab medir o conteúdo uma vez, rolando até o fim, antes de ir ao ponto (leva alguns segundos e a lista se mexe; uma lista que carrega mais itens no fim vai carregá-los). A resposta traz lazy: true, atStart, atEnd e, quando mediu, measured: true com y e maxY; scrollInfo numa lista dessas só sabe as pontas (y: null) e mostra em reported os números que a própria lista informa. Num RecyclerView os números são a estimativa do próprio componente (estimated: true). Uma lista longa demais para medir dá erro unsupported.

Aba lateral

Uma lingueta na borda do laboratório, com o ícone e o nome do plugin, que abre um painel com HTML, CSS e JavaScript seus (isolados num iframe, como na janela de lab.modal). As linguetas de vários plugins ficam empilhadas na mesma borda, sem se sobrepor, e cada lado mostra um painel por vez. A lingueta é um botão: abre e fecha com clique, Enter ou Espaço; Esc fecha.

ChamadaO que faz
const aba = await lab.tab.open({ html, title, icon, side, width, height, mode, trigger, open, remember, id })title: o nome na lingueta (padrão: o nome do plugin). icon: um emoji ou até duas letras. side: 'right' (padrão) ou 'left'. width e height: o tamanho aberto, em px (320, '320px') ou em % da janela ('40%'); padrão 320 px por 70 %. mode: 'overlay' (o painel fica por cima da página, o padrão) ou 'push' (empurra a página). trigger: 'click' (padrão) ou 'hover' (abre ao passar o ponteiro e fecha ao sair; um clique fixa). open: true começa aberta. remember: true guarda se estava aberta ou fechada e volta assim. id distingue as abas de um plugin (até 4).
aba.update({ html, width, … }) · aba.post(dados) · aba.expand() · aba.collapse() · aba.setOpen(bool) · aba.close() · aba.isOpenTroca o conteúdo ou a configuração, conversa com o painel, abre, recolhe e remove a aba. A aba some quando o plugin para.
aba.onMessage(fn) · aba.onToggle((aberta, por) => …) · aba.onClose(fn)O que o painel mandou com window.lab.post; abriu ou fechou (por: user, hover, code, start, other quando outra aba do mesmo lado abriu); a aba foi removida.
No painel: lab.post(dados) · lab.on(fn)Mensagens para o plugin e do plugin, como na janela.

Arrastar do painel para o aparelho

Dentro do painel de uma aba, um elemento pode ser arrastado até o aparelho simulado. Enquanto arrasta, o laboratório desenha uma etiqueta que segue o ponteiro, uma moldura em volta da tela do aparelho e a posição sob o ponteiro; ao soltar, o plugin recebe onde caiu e decide o que fazer (um mock, uma rolagem, só anotar). Esc cancela.

ChamadaO que faz
No painel: lab.draggable(elemento, dados, { label, image })Torna o elemento arrastável. dados (JSON, ou uma função que devolve) volta nos eventos como payload. label é o texto da etiqueta (padrão: o texto do elemento) e image uma miniatura em data:image/… (padrão: a <img> de dentro do elemento, se houver). Devolve a função que desfaz.
aba.onDrag(fn) · aba.onDrop(fn)
no painel: lab.onDrag(fn) · lab.onDrop(fn)		onDrag recebe type: 'start', 'over' (no máximo a cada 100 ms) e 'cancel'; onDrop recebe type: 'drop', também quando solta fora da tela. O evento: { payload, inside, x, y, dpX, dpY, percentX, percentY, windowX, windowY, screen: { width, height, density }, element }.
Campos do eventoinside: o ponteiro está sobre a tela do aparelho. x, y: px da tela do aparelho; dpX, dpY: os mesmos em dp; percentX, percentY: porcentagem da largura e da altura da tela. windowX, windowY: o ponto na janela do app, o sistema de lab.layoutBounds(). element: o componente do app sob o ponto (key, name, testTag, role, texts, actions, bounds) ou null. A posição vem do retângulo da tela no momento, então vale com o aparelho em qualquer escala.

Botões do plugin

Um plugin pode ter botões próprios sem montar HTML: ele diz o texto, o ícone e o que fazer, e o laboratório desenha botões de verdade (com foco pelo teclado, Enter e Espaço). Com placement: 'plugin' (o padrão) eles aparecem no cartão do plugin, no painel Plugins, e na linha dele em Controles › Plugins; com placement: 'toolbar', na barra do aparelho, ao lado de Recriar, Reabrir, Voltar e Tela cheia, com borda tracejada e o nome do plugin na dica. Enquanto o código do clique roda, o botão mostra que está ocupado e ignora novos cliques. Tudo é texto, nunca HTML. Os botões somem quando o plugin para, é desligado ou removido.

ChamadaO que faz
const b = await lab.button({ label, icon, title, id, variant, disabled, placement }, aoClicar) · lab.button('Texto', aoClicar)label: o texto (até 40 caracteres). icon: um emoji ou até dois caracteres. title: a dica (até 200). variant: 'default', 'primary' ou 'danger'. disabled: true desenha desabilitado. placement: 'plugin' ou 'toolbar'. id: o mesmo id de novo atualiza aquele botão (e troca o código do clique, se vier um). Até 12 botões por plugin (erro limit depois disso).
aoClicar({ id, by, button })Roda no plugin, pode ser async. by: 'user' ou 'mcp'; button é o próprio botão (button.update(…)). Um erro aparece nos erros do cartão (fase button('id')) e o plugin continua rodando.
b.update({ label, icon, title, variant, disabled, placement }) · b.remove() · b.onClick(fn) · b.stateMuda só o que for passado; remove o botão; acrescenta outro código de clique (devolve a função que tira); o estado como a página o mostra.
await lab.buttons.list() · await lab.buttons.clear()Os botões do plugin [{ id, label, icon, title, variant, disabled, placement, busy, clicks }]; remove todos.

ChamadaO que faz
lab.ui.text(s, { id })Um bloco de texto.
lab.ui.kv(objeto, { id })Pares chave e valor.
lab.ui.table(linhas, colunas?, { id })Uma tabela (até 500 linhas e 20 colunas).
lab.ui.json(valor, { id })JSON formatado.
lab.ui.image(blob, { id, caption })Uma imagem: um Blob image/* de até 8 MiB. O resultado de lab.screenshot serve direto.

Estado fora da tela

Nem todo estado está num ViewModel da tela. Muitos apps guardam objetos num campo estático: um object Kotlin, um companion, um singleton ou o contêiner de injeção de dependências, que mantém escopos e as instâncias criadas em cada escopo. Esses objetos não aparecem em lab.viewModels(), mas estão no heap. Há três caminhos para chegar até eles, todos só de leitura:

  1. Pela classe que guarda o estático. lab.classes('Contexto') acha o nome; lab.statics(nome) mostra os campos; lab.staticField(nome, caminho) desce até o valor.
  2. Pela classe do objeto. Quando você sabe o tipo, mas não o caminho: lab.instances('pacote.Armazenamento') devolve os objetos vivos desse tipo com seus handles, e lab.inspect / lab.field leem os campos.
  3. De volta até a raiz. lab.referrers(handle) mostra quem segura o objeto (um campo estático, um mapa de um escopo, um ViewModel). Repetindo, você descobre o caminho e depois usa o caminho direto, que é mais barato.
// Um contêiner de injeção de dependências num campo estático: escopos -> instâncias.
// Os nomes abaixo são de exemplo; use lab.classes / lab.statics para achar os do seu app.
const raiz = await lab.statics('com.exemplo.di.ContextoGlobal');
lab.ui.json(raiz.fields, { id: 'raiz' });                 // veja onde está o registro de escopos

// Os objetos de um tipo, onde quer que estejam (escopo, ViewModel, singleton):
const { items } = await lab.instances('com.exemplo.tela.Armazenamento', { limit: 5 });
for (const item of items) lab.ui.json(await lab.field(item.handle, 'dados', { depth: 2 }), { id: item.handle });

// Quem guarda o primeiro deles (para saber o caminho a partir do estático):
if (items[0]) lab.ui.table((await lab.referrers(items[0].handle)).items, ['kind', 'className', 'via', 'field'], { id: 'quem' });

// Uma chave de mapa com pontos vai num array:
const valor = await lab.staticField('com.exemplo.di.ContextoGlobal', ['registro', 'escopos', 'com.exemplo.Tela::id', 'valor']);

// Os CompositionLocals de um componente (o que LocalX.current vale ali):
const arvore = await lab.composeTree();
const no = arvore.owners[0].nodes.find(n => n.testTag === 'salvar');
if (no) lab.ui.kv((await lab.compositionLocals(no.handle, { only: ['LocalContentColor', 'LocalMeuTema'] })).values, { id: 'locals' });

// Seguir um estático ao vivo:
lab.watch({ static: 'com.exemplo.Sessao' }, 'atual.usuario', v => lab.ui.json(v, { id: 'sessao' }));

O que não dá para fazer: chamar métodos, como escopo.get<Tipo>(). Uma consulta lê os campos que o objeto já tem; um objeto que o app ainda não criou não existe para a consulta, e uma classe que o app ainda não inicializou mostra só os nomes dos campos. Uma referência fraca (WeakReference) mostra o objeto enquanto ele existir: caminho.get ou caminho.value.

Custo: statics, staticField e classes custam como field. instances e referrers varrem o heap em páginas de no máximo 40 ms, uma por consulta, e o plugin junta as páginas sozinho; num app grande a resposta pode levar algumas centenas de milissegundos sem travar a tela. Use-as para descobrir o caminho e depois troque por staticField ou field no watch.

Valores e handles

  • Primitivos viram números e booleanos; long fora do intervalo seguro vira string; char e String viram string (cortada em maxString).
  • Objetos viram { $type, $handle, fields } até a profundidade pedida; além dela, só { $type, $handle }.
  • Coleções conhecidas viram { $kind: 'list' | 'set', size, items }, mapas { $kind: 'map', size, entries }, arrays { $kind: 'array', size, items }, enums { $kind: 'enum', name }.
  • Observáveis mostram o valor atual: { $kind: 'StateFlow' | 'LiveData' | 'MutableState' | 'Atomic' | 'Reference' | 'Lazy' | 'ThreadLocal', value } (Reference também cleared, Lazy também initialized). Coleções e observáveis não gastam profundidade; ciclos viram $seen; um corte por tempo ou por número de campos marca $truncated.

Handles e “objeto coletado”

Um handle tem a forma "h<id>.<época>": o id do objeto na VM e a época da VM. Um handle de outra execução é recusado. Guardar um handle não mantém o objeto vivo: quando o app o solta, o coletor o libera e a consulta responde com o código collected (“objeto coletado”). Trate esse erro buscando o objeto de novo, como faz o modelo Observar ViewModel.

Códigos de erro

Os erros de consulta têm error.code: no-apk, collected, bad-handle, bad-path, bad-query, no-class (a classe não está nos DEX), not-initialized (o app ainda não inicializou a classe), bad-class, bad-args, busy (a fila estava cheia ou a VM ficou ocupada; tente depois), failed. lab.screenshot também usa no-image, not-found (a key não está mais na tela) e unsupported.

Custos e limites

Os limites existem para que um plugin não deixe o app mais lento. Valores de src/plugin-host.js e src/apk-worker.js:

  • Eventos: screen vem do quadro que a página já desenhou. Logcat e rede são os lotes que a página já recebe, entregues no máximo a cada 250 ms. A VM só envia linhas do Logcat enquanto algum plugin escuta log ou o painel Logcat está aberto.
  • Consultas à VM: uma por vez, no máximo uma a cada 25 ms, respondidas de um cache por quadro (a mesma pergunta no mesmo quadro não vai à VM). Até 16 consultas pendentes por plugin.
  • Na VM: as consultas esperam numa fila e rodam só entre eventos do app, nunca até 120 ms depois de uma entrada sua, com no máximo 40 ms de consulta por segundo.
  • Mais caras: composeTree e layoutBounds com nomes, uma por segundo por plugin; screenshot, uma a cada 500 ms (uma chamada antes disso espera a vez). instances e referrers varrem o heap em páginas de até 40 ms (no máximo 200 ms com budgetMs), cada página uma consulta na fila.
  • Saída: o painel redesenha no máximo 10 vezes por segundo e só aberto; console, erros e blocos têm limite.

O que não é permitido

  • Escrever no app. Não há API para mudar campos, estado ou arquivos do app. As ações de Agir no lab usam os controles do laboratório (recarregar a tela, mocks, janelas), que você vê em Controles.
  • Chamar métodos. Nenhuma consulta executa código do app ou de bibliotecas. Os valores são lidos dos campos que os objetos já têm, como num heap dump: uma consulta não cria estado (um getter que criaria um objeto não é chamado; o campo é lido).
  • Mexer em nativos protegidos. Plugins não têm acesso a código nativo.

Para mudar o comportamento do app há ferramentas próprias, que deixam rastro no Logcat e no Resumo: Retornos de métodos, Activities ignoradas, Redirecionar hosts e Mock de endpoints, em Controles.

Segurança

O código de um plugin roda com a origem desta página, dentro de um Worker. Ele pode usar fetch como qualquer script da página. O laboratório não acrescenta nenhuma permissão de rede, mas também não impede o que o navegador permite. Use só código seu ou que você revisou.

Logs filtrados

Guarda as últimas 100 linhas do Logcat cuja tag ou mensagem casa com uma expressão regular.

const FILTRO = /erro|error|exception|warn/i;   // edite a expressão
const MAXIMO = 100;
const linhas = [];
let total = 0;
lab.on('log', lote => {
  for (const linha of lote) {
    if (!FILTRO.test(linha.tag + ' ' + linha.message)) continue;
    total++;
    linhas.push({ hora: new Date(linha.wall).toLocaleTimeString(), nível: linha.level, tag: linha.tag, mensagem: linha.message });
  }
  if (linhas.length > MAXIMO) linhas.splice(0, linhas.length - MAXIMO);
  lab.ui.badge(String(total));
  lab.ui.table(linhas.slice().reverse(), ['hora', 'nível', 'tag', 'mensagem'], { id: 'linhas' });
});
lab.ui.text('Esperando linhas que casem com ' + FILTRO + '…', { id: 'linhas' });

Observar um campo de ViewModel

Pega o primeiro ViewModel do app na tela e mostra um campo ao vivo. Quando o objeto é coletado ou a tela muda, procura de novo.

const CAMPO = 'estado.value';   // um caminho: 'contador', 'itens.size', 'estado.value'
let parar = null, atual = null;
async function conectar() {
  const lista = await lab.viewModels();
  const vm = lista.find(item => !item.library) ?? lista[0];
  if (vm?.handle === atual) return;
  parar?.(); parar = null; atual = vm?.handle ?? null;
  if (!vm) { lab.ui.text('Nenhum ViewModel na tela.', { id: 'valor' }); return; }
  lab.ui.badge(vm.className.split('.').pop());
  parar = lab.watch(vm.handle, CAMPO, valor => lab.ui.json(valor, { id: 'valor' }), {
    intervalMs: 250,
    onError: erro => { if (erro.code === 'collected') { atual = null; conectar(); } else lab.ui.text(erro.message, { id: 'valor' }); },
  });
}
lab.on('screen', () => conectar().catch(erro => lab.ui.text(erro.message, { id: 'erro' })));
await conectar();

Árvore Compose resumida

Lista só os nós do Compose com texto, papel ou testTag. A árvore custa dezenas de milissegundos na VM, por isso é lida a cada mudança de tela e no máximo a cada 2 s.

async function mostrar() {

    texto: (no.editableText ?? no.texts.join(' ')).slice(0, 60),
    tag: no.testTag ?? '', ações: no.actions.join(' '),
  })), ['nível', 'nome', 'texto', 'tag', 'ações'], { id: 'arvore' });
}
lab.on('screen', () => mostrar().catch(() => {}));
setInterval(() => mostrar().catch(() => {}), 2000);

Paleta de arrastar

Uma aba com itens que você arrasta até o aparelho; o plugin recebe onde cada um caiu, em px, dp e porcentagem da tela, e o componente que estava embaixo. Cada item tem um campo thumb para uma miniatura (uma data: URL): aqui a do primeiro item vem de um recorte da tela, e qualquer outra imagem do componente entra no mesmo campo.

const itens = [{ id: 'toque', nome: 'Toque', thumb: null }, { id: 'nota', nome: 'Nota', thumb: null }];
const aba = await lab.tab.open({ title: 'Paleta', icon: '🧩', side: 'left', width: 220, height: 380, open: true, html: `
  <style>body{font:13px system-ui;margin:10px} .item{display:flex;align-items:center;gap:8px;padding:8px;margin-bottom:8px;border:1px solid #ccd;border-radius:8px;background:#f6f6fb}
    .item img,.item i{width:32px;height:32px;border-radius:6px;background:#dcdcf5;object-fit:cover} #onde{font:11px ui-monospace,monospace}</style>
  <div id="paleta"></div><p id="onde">Arraste um item até o aparelho.</p>
  <script>
    const paleta = document.getElementById('paleta'), onde = document.getElementById('onde');
    lab.on(itens => {   // o plugin manda a lista; cada item vira um elemento arrastável
      paleta.replaceChildren(...itens.map(item => {
        const el = document.createElement('div'); el.className = 'item';
        el.append(item.thumb ? Object.assign(new Image(), { src: item.thumb }) : document.createElement('i'), item.nome);
        lab.draggable(el, { id: item.id }, { label: item.nome });
        return el;
      }));
    });
    lab.onDrag(e => { onde.textContent = e.type === 'cancel' ? 'Cancelado.' : e.inside ? e.x + ', ' + e.y + ' px' : 'Fora da tela'; });

Paleta de componentes da tela

Uma aba cujos itens são componentes reais da tela: lab.renderVariant renderiza a tela atual numa segunda instância em segundo plano (com outros mocks de endpoint, se você quiser outro estado) e devolve um recorte por componente. Cada recorte vira um item que você arrasta até o aparelho, com a própria imagem seguindo o ponteiro; a aba mostra onde ele caiu. Um recorte sem imagem aparece com o motivo.

const PAPEIS = ['Switch', 'Checkbox', 'Button'];   // o que recortar; um seletor também aceita name, testTag, text, contentDescription, viewId
const LIMITE = 8;
const aba = await lab.tab.open({ title: 'Componentes', icon: '🎨', side: 'left', width: 250, height: '80%', open: true, html: `
  <style>body{font:13px system-ui;margin:10px} .item{padding:6px;margin-bottom:8px;border:1px solid #ccd;border-radius:8px;background:#f6f6fb}
    .item img{display:block;max-width:100%;max-height:80px;pointer-events:none} .item small{color:#667} .erro small{color:#a33} #onde{font:11px ui-monospace,monospace;white-space:pre-wrap}</style>
  <p id="onde">Renderizando a tela em segundo plano…</p><div id="paleta"></div>
  <script>
    const paleta = document.getElementById('paleta'), onde = document.getElementById('onde');
    lab.on(itens => {   // cada recorte vira um item; os que têm imagem podem ser arrastados, com a própria imagem seguindo o ponteiro
      onde.textContent = 'Arraste um componente até o aparelho.';
      paleta.replaceChildren(...itens.map(item => {
        const el = document.createElement('div'); el.className = item.imagem ? 'item' : 'item erro';
        if (item.imagem) { el.append(Object.assign(new Image(), { src: item.imagem })); lab.draggable(el, { nome: item.nome }, { label: item.nome, image: item.imagem }); }
        el.append(Object.assign(document.createElement('small'), { textContent: item.imagem ? item.nome : item.nome + ': ' + item.erro }));
        return el;
      }));
    });
    lab.onDrop(e => { onde.textContent = !e.inside ? 'Solto fora da tela.' : e.payload.nome + '\\npx: ' + e.x + ', ' + e.y + '\\ndp: ' + e.dpX + ', ' + e.dpY
      + '\\n%: ' + e.percentX + ', ' + e.percentY + '\\nsobre: ' + (e.element ? e.element.texts[0] || e.element.role || e.element.name : '—'); });
  </script>` });
await lab.waitReady({ timeoutMs: 20000 }).catch(() => null);
// Uma renderização da tela atual numa segunda instância, que não aparece; todos os recortes saem dela
const variante = await lab.renderVariant({
  // endpointMocks: [{ url: 'https://api.exemplo.com/v1/itens', body: '{"itens":[]}' }],   // os mesmos componentes com outra resposta do servidor
  crops: PAPEIS.map(papel => ({ selector: { role: papel }, all: true })),
  tree: true,   // com a árvore do Compose cada recorte vem com o nome do componente (Button "Salvar")
});
const itens = [];
for (const recorte of variante.images.slice(0, LIMITE)) itens.push({
  nome: recorte.element?.name ?? JSON.stringify(recorte.selector),
  imagem: recorte.image ? await lab.dataUrl(recorte.image) : null,   // sem imagem, o recorte traz o motivo (crop-not-found, no-image…)
  erro: recorte.error?.message,
});
await aba.post(itens);
lab.ui.kv({ recortes: variante.images.length, 'tela parada': variante.settled, 'tempo (ms)': variante.ms.total }, { id: 'paleta' });
